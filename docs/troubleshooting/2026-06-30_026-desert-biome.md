## Two 025 fan-out gaps found + closed (commit 2)

The 025 plan assumed a biome fully drives dressing + water, but two spots
were left hardcoded/uncoupled, blocking any non-temperate biome:

- `Environment.buildDressingConfig` hardcoded the layer kinds to
  `["tree","rock","bush","flower","grass"]` and seeded
  `DEFAULT_DRESSING_COUNTS` under any counts -> a desert biome would still
  dress temperate trees and ignore cactus/yucca. Fixed: derive layers from
  `Object.keys(counts)` (mirrors `PropField.buildSamplerOptions`) and use a
  supplied counts table as the full base (no counts -> temperate defaults).
- `Terrain.waterLevel` returned `cfg.sandLevel`, coupling the water plane to
  the sand colour band. A desert needs high sand coverage but NO water;
  kart buoyancy reads the same value, so a visible/physics mismatch would
  put the kart "in water" on dry dunes. Fixed: `TerrainOptions.waterLevel`
  override; Game.buildWorld passes `biome.waterLevel`. One source of truth
  -> Water plane + kart buoyancy stay consistent for every biome.

Temperate stays bit-identical: `Object.keys` insertion order preserves the
tree,rock,bush,flower,grass layer order; the no-counts fallback + undefined
waterLevel reproduce the pre-biome defaults exactly.

## Notes

- Repo rule forbids committed media, so no PNG is committed; the live
  readout above substitutes for the F3 screenshot (numbers captured from the
  running build via the dev console).
- Flora counts are PER-CHUNK (the dressing framework places `count` per
  streamed chunk). The 026 plan listed world-total-scale numbers; they were
  recalibrated to sparse per-chunk values (cactus 2, sandRock 2, yucca 5,
  dryShrub 30) comparable to temperate (tree 2/rock 1/bush 3/flower 23/
  grass 47) to keep the desert barren and perf in budget.
- sandLevel 3 (high) gives broad sand colour coverage; with water decoupled
  to -100 this no longer implies a water plane. Dune crests + steep faces
  show scrub (colorGrass) / sandstone (colorRock) above/around the sand band.
